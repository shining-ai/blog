# TLS 1.3 ハンドシェイクの詳細

## TLS 1.3 とは

> TLS 1.3（Transport Layer Security 1.3）は、2018年に RFC 8446 として標準化された最新の TLS プロトコルで、前バージョンの既知の脆弱性を排除し、ハンドシェイクを1往復に削減した高速かつ安全なトランスポート層暗号化プロトコルである。

TLS 1.3 は TLS 1.2 と比較して根本的に再設計されており、危険なアルゴリズム（RC4, DES, 3DES, SHA-1, MD5）を完全に排除し、前方秘匿性を必須化した。

**TLS 1.3 ハンドシェイクの流れ：**

1. **ClientHello**：クライアントがサポートする暗号スイート・鍵交換グループ・サポートする拡張を送信。**鍵共有パラメータ（KeyShare）も同時に送信**
2. **ServerHello**：サーバが選択した暗号スイートと自身の KeyShare を返信。ここから**暗号化が始まる**
3. **{EncryptedExtensions}**：暗号化された拡張情報
4. **{Certificate}**：サーバ証明書（暗号化）
5. **{CertificateVerify}**：証明書の秘密鍵による署名
6. **{Finished}**：ハンドシェイク完了の MAC
7. **[Application Data]**：アプリケーションデータ

TLS 1.2 では2往復必要だったハンドシェイクが、TLS 1.3 では**1往復**に削減された。また 0-RTT（ゼロラウンドトリップ）再開も定義されているが、リプレイ攻撃リスクがあるため冪等でない操作には使わない。

**TLS 1.3 の暗号スイート（4つのみ）：**
- TLS_AES_128_GCM_SHA256
- TLS_AES_256_GCM_SHA384
- TLS_CHACHA20_POLY1305_SHA256
- TLS_AES_128_CCM_SHA256
- TLS_AES_128_CCM_8_SHA256

## TLS 1.2 vs TLS 1.3 比較

| 項目 | TLS 1.2 | TLS 1.3 |
|------|---------|---------|
| ハンドシェイク往復数 | 2-RTT | 1-RTT |
| 前方秘匿性 | オプション | 必須 |
| 対応暗号スイート数 | 30+ | 5 |
| 危険なアルゴリズム | 含む（RC4, 3DES 等） | 全廃 |
| 静的 RSA 鍵交換 | あり | 廃止 |
| 証明書の暗号化 | なし | あり |
| 0-RTT 再開 | なし | あり（限定的） |

## TLS 1.3 鍵導出構造（HKDF ベース）

| 段階 | 鍵 | 用途 |
|------|-----|------|
| Early Secret | PSK または 0 から導出 | 0-RTT データ暗号化 |
| Handshake Secret | ECDHE 共有秘密から導出 | ハンドシェイク暗号化 |
| Master Secret | Handshake Secret から導出 | アプリケーションデータ暗号化 |

```python
# TLS 1.3 の概念的な鍵スケジュールデモ
from cryptography.hazmat.primitives.kdf.hkdf import HKDF, HKDFExpand
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.asymmetric.x25519 import X25519PrivateKey
import hashlib

def hkdf_extract(salt: bytes, ikm: bytes) -> bytes:
    """HKDF-Extract"""
    from cryptography.hazmat.primitives.hmac import HMAC
    import hmac as hmac_module
    return hmac_module.new(salt, ikm, hashlib.sha256).digest()

def hkdf_expand_label(secret: bytes, label: str, context: bytes, length: int) -> bytes:
    """TLS 1.3 の HKDF-Expand-Label"""
    # HkdfLabel = length(2B) + "tls13 " + label + context
    tls_label = b"tls13 " + label.encode()
    hkdf_label = (
        length.to_bytes(2, "big") +
        len(tls_label).to_bytes(1, "big") + tls_label +
        len(context).to_bytes(1, "big") + context
    )
    hkdf = HKDFExpand(
        algorithm=hashes.SHA256(),
        length=length,
        info=hkdf_label
    )
    return hkdf.derive(secret)

# ECDHE 鍵交換
client_private = X25519PrivateKey.generate()
server_private = X25519PrivateKey.generate()
client_public = client_private.public_key()
server_public = server_private.public_key()

# 共有秘密の計算
ecdhe_secret = client_private.exchange(server_public)
print(f"ECDHE 共有秘密: {ecdhe_secret.hex()}")

# TLS 1.3 鍵スケジュール（簡略版）
zeros = bytes(32)
early_secret = hkdf_extract(zeros, zeros)           # PSK なし
handshake_secret = hkdf_extract(
    hkdf_expand_label(early_secret, "derived", b"", 32),
    ecdhe_secret
)
print(f"Handshake Secret: {handshake_secret.hex()}")

# ハンドシェイク暗号化鍵
hello_hash = hashlib.sha256(b"ClientHello + ServerHello").digest()
client_hs_key = hkdf_expand_label(
    hkdf_expand_label(handshake_secret, "c hs traffic", hello_hash, 32),
    "key", b"", 16
)
print(f"Client Handshake Key: {client_hs_key.hex()}")

# TLS バージョン確認
import ssl
print(f"\nPython ssl モジュール:")
print(f"  最高対応 TLS: {ssl.PROTOCOL_TLS_CLIENT}")
ctx = ssl.create_default_context()
print(f"  最小バージョン設定: OP_NO_TLSv1 | OP_NO_TLSv1_1 を推奨")
```

## 使用場面

- 全ての HTTPS Web サーバ（nginx, Apache, Caddy での TLS 1.3 有効化）
- API サーバとクライアント間の mTLS（相互 TLS）認証
- gRPC などのサービス間通信
- メールサーバ（STARTTLS / SMTPS での TLS 1.3）
