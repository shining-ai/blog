# X.509 証明書と PKI

## X.509 証明書と PKI とは

> PKI（Public Key Infrastructure）は、公開鍵暗号の信頼性を管理するための仕組みであり、X.509 証明書は公開鍵と識別情報を結びつけてデジタル署名で保証する標準フォーマットである。

インターネット上で相手の公開鍵を信頼するには「この公開鍵は本当にその人のものか」を確認する仕組みが必要である。PKI は認証局（CA）が公開鍵に署名することで信頼の連鎖を構築する。

**X.509 証明書の主要フィールド：**
- **Subject**：証明書の所有者（ドメイン名、組織名など）
- **Issuer**：発行した認証局
- **Public Key**：公開鍵本体と鍵アルゴリズム
- **Validity**：有効期間（Not Before / Not After）
- **Subject Alternative Name（SAN）**：証明書が有効なドメイン名一覧
- **Signature**：発行者 CA の秘密鍵による署名

**PKI の信頼階層：**
1. **Root CA**：自己署名証明書。OS・ブラウザにプレインストールされ無条件に信頼
2. **Intermediate CA**：Root CA が署名した中間認証局。実際の証明書発行を担う
3. **End-Entity 証明書**：サーバや個人の証明書

Root CA の秘密鍵は極めて重要で、通常はオフライン（エアギャップ）環境に保管される。証明書の失効には **CRL**（証明書失効リスト）または **OCSP**（Online Certificate Status Protocol）が使われる。

## X.509 証明書のフィールド

| フィールド | 説明 | 例 |
|-----------|------|-----|
| Version | 証明書バージョン | v3 |
| Serial Number | CA内で一意の識別番号 | 0x1234abcd |
| Subject | 所有者の識別名 | CN=example.com |
| Issuer | 発行者（CA）の識別名 | CN=Let's Encrypt R11 |
| Not Before / After | 有効期間 | 2025-01-01 〜 2025-04-01 |
| Public Key | 公開鍵情報 | ECDSA P-256 |
| SAN | 有効なドメイン名リスト | DNS:example.com, DNS:*.example.com |
| Key Usage | 鍵の用途制限 | Digital Signature |
| CA Signature | 発行者の署名 | SHA256withECDSA |

```python
from cryptography import x509
from cryptography.x509.oid import NameOID, ExtendedKeyUsageOID
from cryptography.hazmat.primitives import hashes, serialization
from cryptography.hazmat.primitives.asymmetric import ec
import datetime

# === 自己署名証明書の作成（学習・テスト用）===
def create_self_signed_cert(domain: str) -> tuple:
    """自己署名 TLS 証明書を生成する"""
    # 秘密鍵の生成
    private_key = ec.generate_private_key(ec.SECP256R1())

    # 証明書情報
    subject = issuer = x509.Name([
        x509.NameAttribute(NameOID.COUNTRY_NAME, "JP"),
        x509.NameAttribute(NameOID.ORGANIZATION_NAME, "Example Org"),
        x509.NameAttribute(NameOID.COMMON_NAME, domain),
    ])

    cert = (
        x509.CertificateBuilder()
        .subject_name(subject)
        .issuer_name(issuer)
        .public_key(private_key.public_key())
        .serial_number(x509.random_serial_number())
        .not_valid_before(datetime.datetime.utcnow())
        .not_valid_after(
            datetime.datetime.utcnow() + datetime.timedelta(days=90)
        )
        # SAN の設定（CN ではなく SAN を使うことが現在の標準）
        .add_extension(
            x509.SubjectAlternativeName([
                x509.DNSName(domain),
                x509.DNSName(f"*.{domain}"),
            ]),
            critical=False,
        )
        .add_extension(
            x509.BasicConstraints(ca=False, path_length=None),
            critical=True,
        )
        .sign(private_key, hashes.SHA256())
    )

    return private_key, cert

private_key, cert = create_self_signed_cert("example.com")

# 証明書情報の表示
print(f"Subject: {cert.subject.rfc4514_string()}")
print(f"Issuer: {cert.issuer.rfc4514_string()}")
print(f"Valid: {cert.not_valid_before_utc} 〜 {cert.not_valid_after_utc}")
print(f"Serial: {cert.serial_number:x}")

# SAN の取得
san = cert.extensions.get_extension_for_class(x509.SubjectAlternativeName)
print(f"SAN: {san.value.get_values_for_type(x509.DNSName)}")

# PEM 形式での出力
pem = cert.public_bytes(serialization.Encoding.PEM)
print(f"\nPEM 証明書 ({len(pem)} バイト):")
print(pem.decode()[:200] + "...")
```

## 使用場面

- HTTPS サーバ証明書の発行（Let's Encrypt による自動化が普及）
- コード署名証明書（アプリ・ドライバの配布時の真正性保証）
- S/MIME メール署名・暗号化
- クライアント証明書認証（相互 TLS / mTLS）
