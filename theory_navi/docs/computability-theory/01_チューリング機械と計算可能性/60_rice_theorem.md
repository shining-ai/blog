# ライス定理

## ライス定理とは

> ライス定理（Rice's Theorem）とは、「チューリング機械が計算する関数（または認識する言語）の非自明な性質は、すべて決定不能である」という定理であり、TM の「振る舞い」に関するあらゆる意味のある問いへの自動解答が原理的に不可能であることを示す。

ライス定理を厳密に述べると次の通りです。性質 P を「半決定可能言語のクラスの部分クラス」とします（つまり P は TM が認識する言語の集合の部分集合）。P が非自明（つまり P ≠ ∅ かつ P ≠ 全ての半決定可能言語）であれば、{<M> | L(M) ∈ P} は決定不能です。

「自明な性質」とは全ての TM が持つ（または全ての TM が持たない）性質で、それ以外は「非自明」です。決定不能となる非自明な性質の例として次のものがあります。「L(M) が空である」「L(M) が有限集合である」「L(M) が正規言語である」「L(M) が特定の文字列 w を含む」「L(M) = Σ*（全文字列受理）である」などが挙げられます。

ライス定理の証明は A_TM への帰着を使います。「M がある固定の TM M_0 と同じ言語を認識するか」という問題に A_TM を帰着させることで証明します。この定理は「プログラムの動作を完全に解析できる汎用静的解析ツールは作れない」という深い実用的含意を持ちます。

## ライス定理の適用例

| 性質 P | 非自明か | 結論 |
|--------|---------|------|
| L(M) = ∅（受理語なし） | はい | 決定不能 |
| L(M) が有限言語 | はい | 決定不能 |
| L(M) が正規言語 | はい | 決定不能 |
| L(M) が特定の語 w を含む | はい | 決定不能 |
| L(M) = Σ*（全語受理） | はい | 決定不能 |
| M が停止する入力が存在する | はい | 決定不能 |
| L(M) ⊆ Σ*（言語の部分集合） | 自明（全 TM が成立） | 決定可能（自明） |

```python
# ライス定理の概念的デモンストレーション

def rice_theorem_demo():
    """
    ライス定理: TM の言語に関する非自明な性質は全て決定不能
    証明のアイデアを概念的に示す
    """
    print("ライス定理: TM の言語に関する性質の決定可能性チェック")
    print()

    properties = [
        ("L(M) が空集合",       True, "非自明: ある TM は空, ある TM は非空"),
        ("L(M) が有限集合",     True, "非自明: TM によって有限/無限が変わる"),
        ("L(M) が正規言語",     True, "非自明: 正規な言語を認識する TM もある"),
        ("L(M) が 'abc' を含む", True, "非自明: 含む TM と含まない TM がある"),
        ("L(M) ⊆ Σ*",          False, "自明: 全ての TM の言語は Σ* の部分集合"),
        ("M は TM である",      False, "自明: 全ての M は定義上 TM"),
    ]

    for prop, non_trivial, reason in properties:
        if non_trivial:
            status = "決定不能（ライス定理により）"
        else:
            status = "自明（ライス定理の適用外）"
        print(f"  性質: '{prop}'")
        print(f"    非自明か: {'はい' if non_trivial else 'いいえ'} ({reason})")
        print(f"    結論: {status}")
        print()

rice_theorem_demo()

# ライス定理の証明のスケッチ
print("="*60)
print("ライス定理の証明スケッチ（A_TM への帰着）")
print("="*60)
print("""
目標: {<M> | L(M) ∈ P} が決定不能であることを示す

前提:
  - P は非自明な性質
  - P に属する言語を認識する TM M_yes が存在する（P ≠ ∅）
  - P に属さない言語（例: 空集合）を認識する TM M_no が存在する

帰着の構成 A_TM ≤_m {<M> | L(M) ∈ P}:
  入力 <M, w> に対して新しい TM M' を構成:
    M'(x) の動作:
      1. M を w 上でシミュレートする
      2. M が w を受理すれば、M_yes(x) をシミュレートしてその結果を返す
      3. M が w を拒否またはループすれば、M' は拒否する

  ここで:
    M が w を受理 → M'(x) = M_yes(x) → L(M') = L(M_yes) ∈ P
    M が w を受理しない → L(M') = ∅ ∉ P（∅ は P に属さないと仮定）

  したがって:
    <M, w> ∈ A_TM ⟺ L(M') ∈ P ⟺ <M'> ∈ {<M> | L(M) ∈ P}

  A_TM が決定不能 → {<M> | L(M) ∈ P} も決定不能
""")

# 実用的な含意
print("実用的な含意:")
examples = [
    "コンパイラが任意の Rust プログラムのメモリ安全性を100%検証できない",
    "静的解析ツールが任意のコードの全バグを発見できない",
    "ウイルス対策ソフトが全マルウェアを確実に検知できない",
    "型チェッカーが完全に正確な型推論をできない（決定可能な部分問題を解いている）",
]
for ex in examples:
    print(f"  - {ex}")
```

## 使用場面

- **静的解析の設計**: プログラムの意味的性質（バグの有無・セキュリティホールなど）の完全な自動検出が不可能であることの理論的根拠となる
- **コンパイラ設計**: 最適化の完全性と決定可能性のトレードオフを理解するために使用する
- **セキュリティ解析**: マルウェア解析が原理的に不完全にしかならないことの証明基盤として使われる
- **形式検証の限界**: モデル検査・定理証明などの手法がカバーできる性質の理論的範囲を把握するために使用する
